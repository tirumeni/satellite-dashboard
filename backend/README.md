# PS-227 Backend Foundation

FastAPI backend for the PS-227 Satellite Change Analysis dashboard. Analysis text is generated by Google's official `google-genai` SDK when `GEMINI_API_KEY` is configured. If Gemini is not configured or its service fails, the backend returns a deterministic mock analysis with HTTP 200 and `source: "mock"`. This phase does not read satellite imagery or perform image processing; generated estimates are explicitly illustrative.

## Setup

From the repository root (Python 3.10+):

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
Copy-Item backend/.env.example backend/.env
uvicorn backend.main:app --reload
```

The API initializes a local SQLite database at `backend/data/ps227.sqlite` (ignored by Git). API documentation is available at `/docs`; health check is `/health`. Copy `backend/.env.example` to `backend/.env` and optionally set `GEMINI_API_KEY` to enable Gemini analysis. Keep this local-only file out of Git; the key must never be copied into a frontend env file.

The default model is `gemini-3.5-flash` and can be changed with `GEMINI_MODEL`. The service uses the official `google-genai` SDK with JSON response MIME type and a Pydantic response schema.

## Database migrations

The app creates missing tables on startup for a zero-setup local run. Use Alembic to manage schema revisions:

```powershell
alembic -c backend/alembic.ini upgrade head
alembic -c backend/alembic.ini revision --autogenerate -m "describe schema change"
```

## API

- `GET /health` — service status.
- `POST /api/analyze` — validates location, change type, before/after years and filters; calls Gemini, stores the structured response, and creates a JSON report snapshot. `/analyze` remains as a compatibility alias.
- `GET /analysis/{id}` — retrieve a stored analysis by its public ID.
- `GET /history?limit=50` — most recent structured searches.
- `POST /history` — record `{location, analysis_type, time_range, original_query}`.
- `POST /save` — save `{analysis_id, title}`.
- `DELETE /save/{id}` — remove a saved analysis by numeric saved-entry ID.
- `GET /reports?limit=50` — recent report snapshots.

`POST /api/analyze` request example:

```json
{
  "location": "Chennai",
  "changeType": "Construction",
  "beforeYear": 2018,
  "afterYear": 2024,
  "filters": {"satellite": "Sentinel-2", "cloudCoverage": 30}
}
```

The response is JSON constrained to a Pydantic response schema and includes summary, detected changes, environmental and infrastructure impact, severity, confidence, affected area estimate, recommendations, metadata, timeline and statistics. The result is a language-model screening estimate only; no imagery is downloaded or analyzed in this phase.

Responses are validated by Pydantic schemas. Invalid request fields return FastAPI's standard `422` response; unknown resource IDs return `404`; database errors return a generic `500` detail without SQL internals.

## Database schema

- `users`: future identity records; no authentication is enabled.
- `analyses`: query, parsed location/type/time/year, coordinates, status, JSON result, timestamp.
- `reports`: JSON report snapshot linked to an analysis.
- `saved_analyses`: user-optional saved title linked to an analysis.
- `search_history`: structured query history; user and analysis links are optional.

All user foreign keys are nullable until authentication is implemented. Relationships and SQLite foreign keys are modeled for future account-scoped data.
